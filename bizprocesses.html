1 Введение

Настоящий документ описывает бизнес-процессы учебного тренажёра оператора

Для каждого из трёх сценариев приведена диаграмма: Алгоритм действий — блок-схема последовательности операций с точками ветвления и параллельными процессами (flowchart).

Завершает документ перечень интерфейсных окон, которые должны быть доступны каждой из ролей системы: Администратор, Преподаватель, Обучающийся.

3.1 Сценарий 1. Настройка учебной среды

Основное действующее лицо — Преподаватель. Процесс охватывает настройку генерации событий нейросетью, формирование и подтверждение эталонных ответов, настройку ролевой модели и предварительную проверку контента.

3.1.1 Задачи пользователя

Преподаватель входит в систему через основное окно входа (1). Преподаватель формирует:

  • Список Учебных задач (7) посредством (8).
  • Список Учебных сценариев (5) посредством (6).
  • Список Тренировок (10) посредством (11).
Уведомление

Преподаватель может формировать эти списки либо в ручном режиме, либо в полуавтоматическом – с использованием ИИ и последующей проверкой и утверждением.

3.2 Сценарий 2. Проведение практического занятия на АРМ-112 (карточки)

Действующие лица — Преподаватель, Обучающийся. Система имитирует входящие вызовы; обучающиеся заполняют карточки событий в эмуляторе АРМ-112.

3.2.1 Задачи пользователя

  1. Преподаватель входит в систему через основное окно входа (1), в списке тренировок (10) выбирает тренировку со статусом Подготовленная, открывает её карточку (11) и инициирует старт занятия — статус меняется на Активная.
  2. Обучающийся входит через основное окно входа (1), в списке тренировок (10) видит назначенную ему активную тренировку, нажимает кнопку Пройти и переходит в Эмулятор АРМ-112 (17).
  3. В ходе занятия система имитирует входящий вызов и выдаёт обучающемуся учебные задачи одну за другой в виде карточек происшествия (14).
  4. Обучающийся заполняет карточку в соответствии с регламентом службы-112 (ведётся отсчёт времени, по умолчанию 30 сек), нажимает Принять — карточка сравнивается с эталоном учебной задачи и блокируется от изменений.
  5. Преподаватель в окне Тренировка (11) наблюдает прогресс в реальном времени и завершает занятие в любой момент — статус меняется на Завершена, редактирование блокируется.
  6. Преподаватель просматривает итоги в списке учебных карточек (15), формирует отчёты в окне Отчёты и аналитика (16).

3.3 Сценарий 3. Проведение практического занятия на АРМ-112 (действия с карточками)

Отличие от сценария 2: преподаватель явно выбирает источник карточек (сгенерированные системой, сформированные обучающимися, смешанный вариант), а обучающийся не заполняет карточку «с нуля», а выполняет действия с полученной карточкой, включая ввод текстовых ответов.

3.3.1 Задачи пользователя

  1. Преподаватель входит в систему через основное окно входа (1), в карточке Тренировка (11) выбирает источник карточек: сгенерированные системой (подтверждённые учебные задачи, окно 7), сформированные обучающимися (окно 15) или смешанный выбор.
  2. Преподаватель инициирует старт занятия — статус тренировки (10) меняется на Активная.
  3. Обучающийся переходит в Эмулятор АРМ-112 (17) кнопкой Пройти (10); система выдаёт ему случайную карточку события (14).
  4. Обучающийся выполняет действия с полученной карточкой — передаёт сообщение в нужные службы, добавляет отработку, вводит текст ответа (например: «Сообщение принято, дежурная бригада направлена на место»); ведётся отсчёт времени (по умолчанию 30 сек).
  5. После завершения действий по карточке система сравнивает их с эталоном, фиксирует тайминг и грамматику, блокирует карточку — и выдаёт следующую случайную карточку, если занятие не завершено.
  6. Преподаватель наблюдает прогресс в реальном времени (11) и завершает занятие в любой момент — статус Завершена, редактирование блокируется.
  7. Преподаватель формирует отчёт по тем же окнам результатов (15, 16).
