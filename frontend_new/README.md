# frontend_new — элементарный веб-клиент тренажёра оператора ДДС

Прототип фронтенда для проверки REST API `../backend_new` и оценки достаточности
полей БД. **Полностью отдельный от бэкенда**: обычные статические HTML-файлы,
ничего не генерируется FastAPI. Страницы открываются даже при погашенном бэкенде
(покажут сообщение «Сервер недоступен»).

Стек: чистые HTML + CSS + JavaScript (`fetch`), без сборщиков и внешних библиотек.

## Быстрый старт (рекомендуемый способ)

1. Запустите **`START.cmd`** (двойной клик). Скрипт:
   - применяет миграции Alembic к БД `system112_trainer`;
   - запускает бэкенд (uvicorn) на `http://127.0.0.1:8000`;
   - запускает статический фронтенд на `http://127.0.0.1:8080`;
   - открывает страницу входа в браузере.
2. Остановка всего стенда — **`STOP.cmd`** (останавливает оба процесса по
   PID-файлам или по фильтру командной строки; чужие процессы не трогает).

### Альтернативный запуск вручную

```cmd
cd backend_new
uvicorn app.main:app --host 127.0.0.1 --port 8000
```
и в другом окне:
```cmd
cd frontend_new
python -m http.server 8080
```
или просто откройте `index.html` двойным кликом (**file://**, работает благодаря CORS `*`).

Вход: `admin` / `admin123` (администратор по умолчанию в dev-режиме).

Адрес API по умолчанию `http://127.0.0.1:8000/api/v1` — его можно поменять
на экране входа (кнопка «Проверить доступность»).

## Пользовательские пути (сценарии ТЗ)

- **Сценарий 1 (настройка системы)** — администратор: `users.html` → создание
  пользователей и ролей; `reference.html` → службы, статусы, группы происшествий;
  `system.html` → мониторинг, настройки, аудит.
- **Сценарий 2 (учебная среда)** — преподаватель: `tasks.html` → создать и
  утвердить задачу (диспозиция + эталон); `scenarios.html` → собрать сценарий из
  утверждённых задач и утвердить его; `trainings.html` → тренировка со сценариями,
  участниками (роли оператора-112 / диспетчера ДДС / диспетчера службы) и активацией.
- **Сценарий 3 (Оператор-112)** — обучающийся: `dashboard.html`/`trainings.html`
  кнопка «Пройти» → `simulator.html`: старт сессии → выдача задачи («Принять вызов») →
  заполнение карточки (JSONB) → «Сохранить и отправить» → машинная оценка.
- **Сценарий 4 (Диспетчеры)** — `simulator.html` для ролей «Диспетчер ДДС»
  (принять → направить в службу) и «Диспетчер службы» (отработать); окно 36.
  После этого преподаватель выставляет итоговую оценку в `cards.html`.
- **Отчёты** — `reports.html`: сводка, отчёт по тренировке, экспорт CSV.

## Особенности

- Токены JWT хранятся в `localStorage` (`access_token`, `refresh_token`);
  при 401 страница перенаправляет на вход.
- Все данные из API экранируются перед выводом (`esc`).
- «Генерация ИИ» задачи на бэкенде пока заглушка (501) — интерфейс сообщает об этом.
- Материалы скачиваются через `fetch` с Bearer-токеном и сохраняются как файл.
- Всё содержимое карточек/эталонов — свободные JSON-объекты (JSONB), форма карточки
  в эмуляторе показывает структуру текущей карточки.
