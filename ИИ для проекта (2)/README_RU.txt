ПРОЧИТАЙ МЕНЯ!
================

БЫСТРЫЙ ЗАПУСК
---------------
Для обычного пользователя теперь нужен только один файл: START.cmd
(то же самое: ЗАПУСТИТЬ_ВСЕ.cmd).

Он автоматически запускает отдельный AI REST, основной backend и frontend,
проверяет готовность сервисов и открывает браузер. Отдельно запускать
ai_rest_server.py, web_ui.py и задавать локальный AI_REST_TOKEN не нужно.

Остановить всё: STOP.cmd
Перезапустить всё: RESTART.cmd
Служебные логи: папка .runtime

ОПИСАНИЕ НОВОЙ ЛОГИКИ ПРОЕКТА
Обновления, реализованные в рамках текущей доработки
Дата: 25.09.2026


1. ОБЩАЯ ИДЕЯ
--------------
Проект представляет собой учебную систему для подготовки операторов Системы-112 и диспетчеров ДДС.

В текущей версии преподаватель работает не только с отдельными учебными карточками, но и со СЦЕНАРИЯМИ — каталогами карточек одного направления.

Пример:

Сценарий «Пожары»
  - Пожар в квартире
  - Пожар в частном доме
  - Пожар автомобиля
  - Пожар в торговом центре
  - Пожар на складе
  - ...
  - всего, например, 40 различных карточек

Сценарий хранится в системе постоянно и может использоваться преподавателем многократно.


2. СЦЕНАРИИ И КАРТОЧКИ
----------------------
Сценарий теперь является каталогом учебных карточек.

Преподаватель может:
  - создать сценарий;
  - добавить в него существующие карточки;
  - создать новые карточки;
  - сгенерировать новые варианты карточек при помощи ИИ;
  - выбрать все карточки сценария;
  - выбрать только отдельные карточки;
  - назначить их одному или нескольким обучающимся.

Например, в сценарии «Пожары» находится 40 карточек. Преподаватель может:
  1) выдать обучающемуся все 40 карточек;
  2) выбрать только 5, 10 или любое другое необходимое количество;
  3) повторно использовать тот же сценарий для другой учебной группы.

При назначении исходные карточки из сценария не удаляются и не изменяются.


3. ПОСЛЕДОВАТЕЛЬНОЕ ПРОХОЖДЕНИЕ
------------------------------
Назначенные карточки проходятся последовательно.

Если преподаватель назначил 10 карточек:
  - обучающемуся открывается первая карточка;
  - остальные ожидают завершения предыдущей;
  - после сдачи первой карточки автоматически открывается вторая;
  - после второй — третья;
  - и так далее до завершения всего назначенного набора.

Обучающемуся не требуется каждый раз возвращаться в список заданий и вручную искать следующую карточку.

Таким образом, назначенный сценарий работает как единая учебная последовательность.


4. КАРТОЧКА ОБУЧАЮЩЕГОСЯ
------------------------
Карточка обучающегося приведена к той же общей структуре, что и карточка преподавателя.

Основное отличие:
  - у преподавателя находится эталонная заполненная карточка;
  - у обучающегося рабочие поля изначально пустые;
  - обучающийся заполняет карточку самостоятельно по ходу разговора с заявителем.

В карточке обучающегося используются те же основные разделы:
  - регистрационные данные;
  - сведения о заявителе;
  - телефон;
  - адрес;
  - обстоятельства происшествия;
  - признаки происшествия;
  - классификатор;
  - привлекаемые службы;
  - другая предусмотренная карточкой информация.

Эталонные значения в обычном режиме обучающемуся заранее не показываются.


5. ДИАЛОГ С ЗАЯВИТЕЛЕМ
----------------------
Диалог с заявителем встроен непосредственно в рабочую карточку обучающегося.

Обучающийся:
  - задаёт вопросы заявителю;
  - получает ответы;
  - анализирует полученную информацию;
  - заносит сведения в соответствующие поля карточки.

Поддерживается озвучивание реплик заявителя.

Предусмотрена работа с локальным Piper. Поддерживается логика голосов, использовавшаяся в проекте ранее. Если необходимые модели Piper отсутствуют, интерфейс может использовать доступный системный русский голос браузера.

Таким образом, карточка и разговор с заявителем представляют собой единое рабочее пространство.


6. АВТОМАТИЧЕСКОЕ ОПРЕДЕЛЕНИЕ КЛАССИФИКАТОРА
--------------------------------------------
Доработана работа с классификатором происшествий.

Обучающийся последовательно выбирает признаки происшествия.

Система фильтрует подходящие варианты классификатора.

Пока возможных вариантов несколько — обучающийся продолжает уточнять признаки.

КОГДА ПО ВЫБРАННЫМ ПРИЗНАКАМ ОСТАЁТСЯ РОВНО ОДИН ВАРИАНТ, КОД ПРОИСШЕСТВИЯ УСТАНАВЛИВАЕТСЯ АВТОМАТИЧЕСКИ.

Дополнительно нажимать кнопку выбора единственного оставшегося классификатора не требуется.


7. АВТОМАТИЧЕСКИЙ ПОДБОР СЛУЖБ
------------------------------
После определения классификатора система автоматически подбирает службы, предусмотренные для данного типа происшествия.

Например, в зависимости от карточки могут быть предложены:
  - пожарная охрана;
  - полиция;
  - скорая медицинская помощь;
  - аварийная газовая служба;
  - другие предусмотренные классификатором службы.

ВАЖНО:
автоматический подбор является исходным предложением системы, а не жёстко заблокированным решением.

Обучающийся может управлять составом служб:
  - добавить службу;
  - исключить службу;
  - изменить выбранный состав;
  - определить основную службу, если это предусмотрено интерфейсом.

То есть система подсказывает базовый состав, но обучающийся принимает рабочее решение сам.


8. ДВА РЕЖИМА РАБОТЫ
--------------------
ВАЖНО: прежняя экспериментальная система «Лёгкий / Средний / Сложный» и адаптивная сложность больше НЕ используются.

В актуальной версии предусмотрены только ДВА режима:

  1. ОБУЧЕНИЕ
  2. ТЕСТИРОВАНИЕ

Режим выбирает преподаватель при назначении задания/сценария.


9. РЕЖИМ «ОБУЧЕНИЕ»
--------------------
Этот режим предназначен для формирования навыка и помощи обучающемуся в процессе работы.

Если обучающийся некоторое время не выполняет полезных действий (ориентировочно 10 секунд), система начинает его подталкивать.

Принцип работы:
  1) система отслеживает бездействие;
  2) выбирает одно из ещё не заполненных полей;
  3) показывает учебную подсказку по этому полю на основе эталонной карточки;
  4) само поле автоматически НЕ заполняется — обучающийся должен внести информацию сам;
  5) если снова возникает период бездействия, система может раскрыть следующую подсказку.

Пример:

  Подсказка:
  «Обратите внимание на поле “Адрес происшествия”.
   Эталонное значение: ул. Королёва, д. 7А.»

Таким образом, система не выполняет работу вместо обучающегося, а постепенно направляет его.

Полезное действие обучающегося сбрасывает таймер ожидания. К таким действиям относятся, например:
  - заполнение поля;
  - изменение данных карточки;
  - ввод вопроса заявителю;
  - продолжение диалога;
  - иные рабочие действия в карточке.

Одно и то же уже раскрытое поле не должно повторно использоваться как новая подсказка.

Уже заполненное обучающимся поле также не должно раскрываться системой без необходимости.


10. РЕЖИМ «ТЕСТИРОВАНИЕ»
------------------------
В режиме тестирования обучающийся должен пройти карточку полностью самостоятельно.

В этом режиме НЕТ:
  - автоматических подсказок;
  - раскрытия эталонных ответов;
  - подталкивания после бездействия;
  - автоматического показа правильного значения поля.

Запрет реализован не только визуально в интерфейсе, но и на стороне серверной логики.

При этом штатная логика классификатора и автоматического формирования первоначального состава служб сохраняется как часть самой рабочей системы, а не как учебная подсказка.


11. РОЛЬ ПРЕПОДАВАТЕЛЯ
----------------------
Преподаватель управляет учебным процессом.

Он может:
  - создавать сценарии;
  - создавать и редактировать карточки;
  - формировать эталонное содержание карточки;
  - выбирать весь сценарий или отдельные карточки;
  - назначать выбранный набор обучающимся;
  - выбирать режим «Обучение» или «Тестирование»;
  - повторно использовать существующие сценарии;
  - проверять результаты выполнения.

Итоговая оценка и педагогическое решение остаются за преподавателем.


12. ПРИМЕР ПОЛНОГО ЦИКЛА
------------------------
Пример работы преподавателя:

1. Преподаватель открывает сценарий «Пожары».
2. В сценарии находится 40 карточек.
3. Преподаватель выбирает, например, 12 карточек.
4. Выбирает обучающихся.
5. Выбирает режим «Обучение» или «Тестирование».
6. Назначает задание.

Работа обучающегося:

1. Открывается первая карточка.
2. Обучающийся начинает разговор с виртуальным заявителем.
3. По полученной информации заполняет карточку.
4. Выбирает признаки происшествия.
5. Когда остаётся один подходящий классификатор, он устанавливается автоматически.
6. Система автоматически предлагает соответствующие службы.
7. Обучающийся при необходимости корректирует состав служб.
8. Завершает и сдаёт карточку.
9. Автоматически открывается следующая назначенная карточка.
10. Процесс продолжается до выполнения всех 12 карточек.

В режиме «Обучение» при длительном бездействии система постепенно помогает подсказками.
В режиме «Тестирование» обучающийся выполняет всё без учебных подсказок.


13. ИСПРАВЛЕНИЯ ЗАПУСКА WINDOWS
-------------------------------
В ходе работы была исправлена проблема запуска командных файлов Windows, при которой могли появляться сообщения вида:

  'f' is not recognized as an internal or external command
  '�' is not recognized as an internal or external command

Причиной были кодировка и формат переносов строк в .cmd-файлах.

START.cmd, BUILD_UI.cmd и START_CONSOLE.cmd были приведены к безопасному для Windows формату.

Основной запуск проекта выполняется через:

  START.cmd

При необходимости диагностики можно использовать:

  START_CONSOLE.cmd


14. АВТОМАТИЧЕСКАЯ СБОРКА ИНТЕРФЕЙСА
------------------------------------
При запуске проекта предусмотрена пересборка актуального интерфейса, чтобы изменения React-части попадали в рабочую версию программы.

Это сделано для того, чтобы пользователь запускал проект обычным START.cmd и не выполнял дополнительные действия вручную.

16. ВАЖНО ДЛЯ ДАЛЬНЕЙШЕЙ РАЗРАБОТКИ
-----------------------------------
При последующих изменениях проекта следует исходить именно из этой модели.

Не возвращать без отдельного решения:
  - уровни «Лёгкий / Средний / Сложный»;
  - фиксированную/адаптивную сложность.

Текущая педагогическая модель:
  - «Обучение» — система помогает после периода бездействия;
  - «Тестирование» — система не предоставляет учебных подсказок.
