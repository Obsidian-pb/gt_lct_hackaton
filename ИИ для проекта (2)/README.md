# ИИ для проекта — пробная версия

## Вставить свой ключ GigaChat

Дважды нажмите **ВСТАВИТЬ_КЛЮЧ.cmd** в папке программы. Вставьте свой **ключ авторизации** из кабинета GigaChat (правой кнопкой мыши или Ctrl+V), затем нажмите Enter. Символы скрыты при вводе. Ключ сохранится в `config.local.json`, приложение автоматически перезапустится и откроется. Для замены ключа запустите этот файл снова.

По умолчанию используется личный доступ `GIGACHAT_API_PERS` и модель Pro. Если локальная конфигурация уже существует, её модель, scope и настройки сертификатов сохраняются. Нужны доступ к выбранной модели и установленный Python, как для обычного запуска. Доступность API проверяется при обращении к модели в приложении. Если порт занят другой копией, её процесс не останавливается: ключ останется сохранён, а окно покажет причину невозможности перезапуска.

`config.local.json` и временные файлы записи исключены из Git. Сам ключ не передаётся через аргументы команд и не печатается в консоли. Ваш существующий общий ключ в AppData этот помощник не изменяет.

## Полная карточка обучающегося и адрес на карте

1. Откройте «Карточки», создайте карточку и проверьте эталон. В блоке «Разговор для обучающегося» задайте первую реплику, затем утвердите карточку.
2. Войдите как «Обучающийся»: утверждённая карточка появится в тренировках. Заявитель отвечает через GigaChat, данные в полную форму вносит ученик. Телефон для перезвона уточняется вопросом.
3. «Задать вопрос голосом» запрашивает микрофон; распознанный текст можно исправить. «Послушать заявителя» использует голос браузера. При отсутствии поддержки используйте текст.
4. В адресном поиске введите, например, «Королева 7а» и выберите результат. Заполнятся улица/дом/координаты, появится точка. Местная копия OSM Железногорска работает без интернета; дата исходной выгрузки неизвестна, полнота адресов ограничена имеющимися данными.
5. После сдачи откройте «Результаты» у преподавателя: карточка, разговор, предварительная проверка GigaChat и окончательное решение преподавателя.

Для ранее утверждённой карточки есть кнопка «Добавить в тренировки обучающегося». Если перенесли модуль на другой компьютер без папки `data`, нажмите «Проверить доступность тренировки». Старые учебные сценарии открываются в полной форме; их прежние семь критериев оценки не меняются автоматически.

## После обновления репозитория / ошибка «Не найдено» при входе ученика

1. Обновите **всю папку модуля**, а не только React-сборку. Сервер `web_ui.py`, его Python-модули и каталог `ui/` должны быть из одной версии. Папка в репозитории может называться `ИИ для проекта (2)`.
2. Сохраните текущую работу. Запустите **RESTART.cmd из обновлённой папки**. Он перезапускает только сервер этого модуля на 8878 и отказывается останавливать другую программу или копию из другой папки. Перезапуск не удаляет `data/` и данные браузера.
3. В открывшемся окне выберите «Обучающийся» и «Войти». Страница — `http://127.0.0.1:8878/student`.

Причина типичного случая: Python-сервер запущен скрыто и продолжает использовать старый код после обновления файлов. Прежний `START.cmd` мог повторно открыть именно его. Новый запуск сравнивает отпечаток версии и больше не переиспользует устаревший процесс и не переносит приложение молча на случайный порт.

Диагностика: `http://127.0.0.1:8878/health` показывает `root` (папку запущенной копии), `revision` (версию), `pid` и `pages`. Если нет `revision` или `/student` в `pages`, работает прежний сервер. Если `root` указывает на другую папку, сначала завершите её сервер или запустите `RESTART.cmd` из той папки; новую копию открывайте после освобождения порта. Если ошибка осталась на полностью остановленном и вновь запущенном сервере, пришлите содержимое `/health` и текущую ветку/коммит репозитория. Очистка данных браузера для исправления этой ошибки не нужна.

Отдельный ИИ-модуль с простым интерфейсом в браузере и дополнительной консолью. Не импортирует код симулятора и не изменяет его файлы.
Python 3.10 или новее, сторонние Python-библиотеки не нужны. GigaChat требует интернет и настроенный доступ.
На главной странице — начальный экран по макету hero.svg. Кнопка «Войти» сразу открывает панель преподавателя, без логина, пароля и проверки роли. Раздел «Карточки» открывает мастерскую карточек по ТЗ и замечаниям команды от 21.09.2026. Форма предназначена для согласования и не объявляется утверждённой ведомственной формой. Панель обучающегося также использует полную форму; старый отдельный клиент `/training` оставлен для совместимости.

## Панель преподавателя

Начальный экран, панель преподавателя и мастерская карточек работают на **React**. Исходники и инструкции сборки находятся в `frontend/README.md`. Готовая сборка включена в проект: для обычной работы достаточно **START.cmd**, устанавливать Node.js не требуется. Существующий учебный стенд `/training` сохранён отдельно, его функции доступны как прежде.

Панель `http://127.0.0.1:8878/teacher` содержит меню, быстрые действия и последние сохранённые тренировки. Раздел «Сценарии» открывает каталог многоразовых наборов карточек: преподаватель может хранить, дополнять и повторно назначать сценарий целиком либо выдавать выбранные карточки одному или нескольким обучающимся. Название группы сохраняется в назначении; итоговые оценки — только подтверждённые преподавателем, по шкале 2–5. Сообщения и серверная авторизация пока не подключены. Имя в шапке меняется в настройках и хранится в этом браузере. «Завершить работу» возвращает к начальному экрану, сохраняя карточки. Это навигация, не серверная авторизация.

Новая панель не создаёт базу данных и не меняет сохранённые карточки. Проверка навигации, сохранности карточек, профиля, завершения работы и мобильной версии: `node tests/check_teacher_ui.mjs`.

## Мастерская карточек — без базы данных

Откройте **START.cmd** и раздел «Карточки» или сразу `http://127.0.0.1:8878/cards`. Задайте категорию, тему и количество **от 1 до 100 за один запуск**, нажмите «Сгенерировать». Запросы GigaChat идут последовательно, по одной карточке: большая подборка требует времени. Готовые результаты сразу появляются в списке. Остановка применяется после текущего запроса. При ошибке или обновлении страницы можно продолжить оставшиеся позиции; уже готовые карточки не генерируются заново. Закрытая вкладка не продолжает очередь в фоне.

В карточке доступны исходное сообщение, заявитель и три телефона, подробный адрес и координаты, классификация, обстоятельства, регистрация, контроль и предлагаемые службы. Дополнительные поля раскрываются по необходимости. Можно создать пустую карточку вручную. Модель не заполняет за систему АОН, внешний номер 112, геокодирование, время и авторство контроля.

Преподаватель редактирует черновик, вводит имя и утверждает **каждую карточку отдельно**. После этого поля блокируются. «Вернуть на доработку» снимает действующее утверждение, сохраняя прежнюю утверждённую версию в истории. Имя преподавателя здесь вводится вручную; проверки учётной записи нет. «Проверить поля» проверяет формат, не достоверность фактов и не педагогическое качество.

Новые карточки хранятся **только в localStorage текущего браузера и адреса сайта**. Сервер не записывает их в `data/` или базу данных. Доступен экспорт всей подборки или одной карточки в JSON с версиями утверждения. Импорт пока не реализован. Очистка данных браузера удалит локальную подборку; другой браузер или порт не видит её. При нехватке места интерфейс предлагает скачать данные и продолжает работать в памяти.

Классификатор `112-v046-24` импортирован из предоставленного Excel: 24 группы, 1283 уникальных кода, 61 позиция службы. В форме сначала выбирается группа, затем доступные признаки. Если после выбора всех доступных признаков остаётся ровно одна строка классификатора, итоговый код подставляется автоматически. При нескольких вариантах итоговый тип можно выбрать вручную. Можно оставить часть признаков «Любой»: генератор переберёт только подходящие строки. Переключение группы сбрасывает несовместимые признаки. «Человек тонет», «Человек утонул» и «Всплыл утопленник» — разные строки. Неизвестные дополнительные признаки хранятся отдельно от «Нет».

Для каждой строки сохранены исходный номер строки, тип ЕКП, главная служба и все заполненные условные ячейки служб. При создании предлагаются только службы из столбца «Главная служба»; полный состав преподаватель выбирает в окне с поиском, сверяясь с раскрываемой таблицей условий. Условные столбцы не применяются автоматически: их сочетания требуют согласования правил. При нескольких главных службах в источнике единственная главная не назначается произвольно. Старые карточки `demo-*` доступны и могут быть утверждены; новые создаются по импортированным кодам.

Дизайн создания карточек адаптирован из `card making.svg`. Учебные режимы, таймер, эталоны и назначение обучающихся подключены к сценарию-каталогу. Сами каталоги сценариев сохраняются в localStorage браузера, а созданные учебные сессии — серверным учебным движком. Реальные передачи службам и внешняя база данных не подключены.

Проверки: `python -m unittest discover -s tests -v`; `node tests/check_cards_ui.mjs` (Playwright/Edge, тестовая модель); `python smoke_cards_live.py` (три реальных запроса GigaChat, результаты в `test-output/cards-live/`).

## Два учебных варианта на GigaChat

- **Оператор 112:** модель играет заявителя. Обучающийся задаёт вопросы и заполняет пустую карточку.
- **Диспетчер ДДС:** обучающийся получает заполненную карточку от имитируемой 112, сверяет её с доступным уточнением и звонит сотруднику учебной службы, которого играет модель.

Вариант выбирается при создании задания и при начале обучения. В каждом варианте есть готовый пример; его нужно просмотреть и утвердить. Старые карточки автоматически относятся к варианту оператора 112.

Для проверки ДДС: «Карточки заданий» → вариант «Диспетчер ДДС» → «Готовый пример» → утвердить → «Обучение» → тот же вариант → начать. Карточка уже заполнена. Сравните её с уточнением от 112, исправьте ошибки и нажмите «Позвонить службе».

После соединения можно выбрать помеху на следующую реплику: «Слышно только начало» или «Обрыв». Это ручные тестовые события модели, без настоящего SIP и аудиошума. При обрыве нажмите «Перезвонить службе» и повторите сообщение. Модель не получает потерянные слова.

У ДДС преподаватель рассматривает 11 пунктов: семь полей карточки и четыре критерия действий. Итоговая оценка по-прежнему только его. Подробные границы нашей части и обмен данными описаны в **AI_CONTRACT.md**.

## Работа в браузере

Дважды нажмите **START.cmd**. При первом запуске программа сначала попросит собственный ключ GigaChat, сохранит его только в локальном `config.local.json`, а затем откроет начальный экран с кнопкой «Войти». Консоль для обычной работы не нужна. Прежние учебные экраны доступны по ссылке «Учебный прототип» или `/training`. Сервер работает локально на `127.0.0.1:8878`; повторный запуск открывает уже запущенный экземпляр. Только прежние учебные задания и работы берутся из папки `data/`. После обновления серверного кода требуется перезапуск сервера.

- **Обучение:** введите имя, нажмите «Начать обучение». Слева — разговор и кнопка микрофона, справа — поля карточки. «Мои работы» показывает сохранённые сеансы этого имени.
- **Карточки заданий:** создайте задание с GigaChat или откройте готовый пример. Исправьте сценарий, сведения заявителя, эталон и критерии. Введите имя преподавателя и нажмите «Утвердить и выдать в обучение».
- **Проверка работ:** откройте сданную работу, изучите разговор и разбор ИИ. Выберите своё решение по каждому полю, введите оценку и опубликуйте итог. Обучающийся увидит только этот итог.

Записи в карточке сохраняются кнопкой «Сохранить карточку», перед вопросом и при переходе в другой раздел. До этого черновик полей хранится в текущем браузере. При сдаче карточка сохраняется и блокируется; затем запускается проверка ИИ. Если модель недоступна, преподаватель может повторить проверку.
Изменения сценария сохраняются кнопкой «Сохранить черновик» либо при утверждении.

Кнопка **«Микрофон»** запрашивает разрешение браузера и записывает вопрос в поле ввода. Проверьте текст и нажмите «Спросить». Используйте Chrome или Edge; распознавание зависит от доступности сервиса браузера. Ответы заявителя пока текстовые.

Это локальный пробный интерфейс, а не система разграничения доступа: все разделы доступны владельцу компьютера. Не запускайте консоль одновременно с интерфейсом для изменения одних и тех же работ. Локальный сервер сериализует операции браузера; для рабочего многопользовательского продукта понадобится бэкенд команды.
Файлы хранилища и конфигурации через веб-сервер не раздаются. Адреса API защищены случайным токеном страницы и проверкой источника запроса; это не заменяет авторизацию ролей.

Для ручного запуска: `python web_ui.py`. Дополнительно: `--port 8878`, `--no-browser`, `--data-dir путь`. Ошибка запуска без консоли записывается в `ui-error.log`.

## Дополнительный консольный режим

1. Дважды нажмите **START_CONSOLE.cmd**. На этом компьютере используется имеющийся Python; на другом нужен Python с командой `py`.
2. Выберите **2 — готовый пример** и учебный вариант. Прочитайте сценарий и эталон.
3. При необходимости исправьте поля. Выберите **2 — утвердить**, введите имя преподавателя и подтвердите `да`.
4. В главном меню выберите **5 — начать обучение**, учебный вариант и имя обучающегося. Если в этом варианте утверждена одна карточка, начнётся именно она; если несколько — одна выбирается случайно. Черновики не выдаются. Утверждённые карточки остаются доступными после перезапуска.
5. Пишите вопросы обычным текстом. Например: `Назовите адрес`, `Внутри кто-нибудь есть?`, `Сколько этажей?`.
6. `/card` покажет поля. Заполняйте самостоятельно: `/set address Учебный город, улица Лесная, 12`.
7. `/voice` откроет окно микрофона. Разрешите доступ, произнесите вопрос, исправьте текст и передайте в консоль. В консоли подтвердите отправку.
8. `/finish` сдаёт работу. ИИ готовит предварительную проверку, а ученик видит только статус ожидания преподавателя.
9. В главном меню **4 — сданные работы обучающихся**: разговор, карточка, эталон, критерии, подсказки и замечания ИИ. Здесь появляются только сданные работы, а сами утверждённые задания можно просмотреть в пункте **7 — утверждённые карточки**.
10. Преподаватель отдельно принимает, отклоняет или исправляет замечание по каждому полю, вводит свою оценку 2–5 и итог. Только после его подтверждения результат доступен ученику через пункт **6**.

**1 — создать задание с ИИ** позволяет описать другую ситуацию. Полученный черновик обязательно проверяется преподавателем.
Готовый пример — фиксированный сценарий, а не имитация сетевого ИИ: ответы заявителя, подсказки и проверку в нём также делает настоящий GigaChat.

## Уровни и команды

- В актуальном веб-интерфейсе используются только режимы «Обучение» и «Тестирование».
- «Обучение» автоматически раскрывает по одному эталонному полю после паузы в работе.
- «Тестирование» не предоставляет эталонных подсказок.
- `/set CODE Текст` — записать поле; `/card` — значения и коды; `/history` — диалог.
- `/back` — сохранить и выйти без сдачи; `/help` — команды.
- После сдачи разговор и карточка заблокированы. Ошибка API при проверке не теряет работу: преподаватель повторяет проверку из пункта 4.

Поля: `address`, `incident`, `people`, `injured`, `floors`, `entrance`, `access`.
Команды ДДС в консоли: `/call` — позвонить / перезвонить, `/hangup` — завершить, `/link clear`, `/link partial`, `/link drop` — условия доставки следующей реплики.
Текст из микрофона **не исправляется незаметно моделью**: пользователь видит и подтверждает его.
Голосовой ввод требует Chrome/Edge с поддержкой SpeechRecognition. Наличие браузера не гарантирует доступность сервиса распознавания; возможна зависимость от интернета и политики организации. При отказе показано сообщение и доступен текстовый ввод.
В веб-интерфейсе реплики заявителя могут озвучиваться через локальный Piper; если локальная модель голоса недоступна, используется доступный русский голос браузера. Аудиозаписи диалога не сохраняются.

## Первый запуск на другом компьютере

Передаваемая сборка не содержит чужого ключа. Запустите `START.cmd`: до открытия интерфейса появится отдельное окно для ввода ключа GigaChat. Ключ сохраняется только в `config.local.json` рядом с программой. Для замены ключа используйте `CHANGE_AI_KEY.cmd`.

Если Python 3 не найден, `START.cmd` предложит установить Python 3.12 для текущего пользователя с официального `python.org`. Установка выполняется только после подтверждения пользователя. Node.js для работы интерфейса не требуется: готовая сборка включена в проект, а Windows-версия esbuild лежит локально.

## Настройка GigaChat

Порядок выбора конфигурации: `AI_PROJECT_CONFIG`, затем `FIRE_SIM_GIGACHAT_CONFIG`, затем `config.local.json` в этой папке, затем существующий `%APPDATA%/FireSimulation/gigachat_config.json`.
Существующий файл читается; ключ не копируется и не попадает в задания, результаты или отчёты.
Ключ также можно передать переменной `GIGACHAT_CREDENTIALS`.
Модель переопределяется переменной `AI_PROJECT_MODEL`. Значение `pro` выбирает доступную Pro-модель через список моделей API.

Для переноса на другой компьютер можно создать свой `config.local.json`:

```json
{
  "authorization_key": "ВАШ_КЛЮЧ_АВТОРИЗАЦИИ",
  "scope": "GIGACHAT_API_PERS",
  "model": "pro",
  "verify_ssl": true,
  "base_url": "https://api.giga.chat/v1"
}
```

При необходимости задайте `ca_bundle` — путь к файлу доверенных сертификатов. Если в унаследованной конфигурации уже указан `verify_ssl: false`, модуль использует этот режим; автоматически проверка сертификатов не отключается.
Не передавайте команде файл с ключом. [Официальная документация авторизации](https://developers.sber.ru/docs/ru/gigachat/api/reference/rest/gigachat-api).

## Передача коллегам и границы прототипа

`ai_core.py` — ядро, `provider.py` — заменяемый адаптер модели, `console.py` — консольный клиент. `web_ui.py` и `ui/` — отдельный локальный браузерный клиент.
`voice.py` и `microphone.html` — отдельный способ получить текст вопроса. Браузер микрофона получает только свою страницу, без ключа, сценария, эталона или отчёта.

Минимальный пример вызовов из будущего серверного приложения:

```python
from ai_core import Engine
from provider import GigaChat

engine = Engine(GigaChat(), directory="exercise_data")
task = engine.draft("Пожар в гараже", "medium")
# Преподаватель проверяет task и исправляет его через edit_task().
engine.approve(task["id"], "Преподаватель")
session = engine.start(task["id"], "Обучающийся")
reply = engine.ask(session["id"], "Назовите адрес")
engine.set_field(session["id"], "address", "Запись ученика")
engine.submit(session["id"])
assessment = engine.assess(session["id"])
# assessment только преподавателю; затем finalize() с его решениями.
student_payload = engine.student_view(session["id"])
```

Операции ядра: `draft`, `sample`, `edit_task`, `approve`, `approved_tasks`, `start_assigned`, `start`, `ask`, `hint`, `set_field`, `submit`, `assess`, `finalize`, `student_view`.
Для автоматической выдачи используйте `start_assigned(student)`: выбирает одну из сохранённых утверждённых карточек и возвращает только представление обучающегося. При единственной карточке она доступна для повторных прохождений; при нескольких выбор случайный, повторения возможны. `approved_tasks()` — внутренний каталог / данные преподавателя, содержащие эталон; ученику его не выдавать.
`load` и `list_items` содержат закрытые материалы: не выдавать их ученику в будущем API.
Общая система должна сама проверять права доступа преподавателя/ученика, владение сеансом, хранить секреты и сериализовать изменения.
Это однопользовательский локальный прототип: меню ролей и имена **не являются аутентификацией**. Файлы на диске доступны владельцу компьютера. Многопользовательская работа пока не поддерживается.

Состояния задания: `draft → approved`. Состояния работы: `active → submitted → pending_teacher → reviewed`.
Сеанс содержит копию утверждённого задания и контрольную сумму. Изменение оригинала не меняет эталон начатой работы.
До `reviewed` в `student_view` нет заключения ИИ, эталона и скрытых фактов. После — только опубликованное решение преподавателя.
Проверка цитат автоматическая: неподтверждённые цитаты ИИ удаляются и помечаются для ручной проверки. Это не доказывает правильность интерпретации — её оценивает преподаватель.
Вес критерия передаётся проверяющему как часть рубрики; автоматической итоговой оценки и скрытых штрафов нет. Шкала 2–5 временная.

Файлы упражнений находятся в `data/`. Каждое изменение сохраняется через временный файл с последующей заменой. `/back` позволяет продолжить позже.
Прототип не заменяет утверждённые учебные методики. Следующий шаг после пробного запуска — согласовать карточку и критерии по ТЗ.

## Последовательные сценарии: обучение и тестирование

При назначении сценария преподаватель выбирает один из двух режимов: **Обучение** или **Тестирование**. Сложности и адаптивных уровней в назначении больше нет. В сценарии одновременно активна только одна карточка. После сдачи система автоматически активирует и открывает следующую карточку, пока обучающийся не выполнит весь выбранный преподавателем набор.

В режиме **Обучение** система отслеживает полезную активность в карточке и диалоге. Если примерно 10 секунд обучающийся не заполняет поля, не вводит вопрос и не получает новую реплику, система раскрывает **одно ещё не заполненное поле утверждённого эталона**. Подсказка не заполняет карточку автоматически: обучающийся видит название поля и эталонное значение и продолжает работу самостоятельно. При следующей паузе может быть раскрыто ещё одно поле.

В режиме **Тестирование** автоматические и ручные эталонные подсказки отключены. Сервер отклоняет запрос на раскрытие эталона для тестовой работы. Последовательная выдача карточек при этом работает так же: после сдачи одной карточки сразу открывается следующая.
