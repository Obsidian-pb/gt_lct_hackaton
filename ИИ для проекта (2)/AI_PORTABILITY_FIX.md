# Исправление выбора ИИ-провайдера

Предыдущая сборка называла подключение «ИИ», но всегда отправляла ключ в OAuth GigaChat. Поэтому корректный API-ключ OpenAI отклонялся до генерации.

Теперь окно CHANGE_AI_KEY.cmd позволяет выбрать OpenAI, GigaChat, Gemini, Claude или OpenAI-совместимый API. Для собственного API указываются базовый HTTPS-адрес и модель. Простое переименование ключа не используется: авторизация, конечные адреса, формат запросов и чтение ответов зависят от провайдера.

## Запуск с OpenAI

1. Распакуйте архив полностью. Сохраните прежнюю папку с учебными данными отдельно.
2. Запустите START.cmd. Если настройки уже существуют, сначала откройте CHANGE_AI_KEY.cmd.
3. Выберите OpenAI, вставьте свой API-ключ, оставьте модель auto и сохраните.
4. После изменения уже работающей программы запустите RESTART.cmd.
5. Проверьте CHECK_AI.cmd, затем создайте одну учебную карточку.

## Что ещё исправлено

- JSON Schema передаётся в формате выбранного провайдера; у Claude используется Messages API.
- Назначенная вручную модель не подменяется и не требует доступа к списку моделей для генерации.
- Отличаются ошибки неверного ключа, доступа, квоты, модели, сети и TLS.
- Диагностика не обещает успешную генерацию по одному доступному списку моделей.
- Старые настройки GigaChat поддерживаются; ключ другого сервиса не пробуется на нескольких провайдерах.
- Дополнительный корневой сертификат подготавливается только для GigaChat, загрузка не отключает проверку TLS.
- Запросы с ключами не следуют HTTP-перенаправлениям.
- PowerShell-файлы сохранены в UTF-8 с BOM для Windows PowerShell 5.1.
