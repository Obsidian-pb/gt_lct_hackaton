# Связка интерфейса с выделенным AI REST сервером

## Архитектура

Для учебного диалога с заявителем используется цепочка:

`Браузер обучающегося → REST API основного приложения → выделенный ai_rest_server.py → AITUNNEL`

Браузер **не обращается напрямую** к `:8890`. Это сделано специально: иначе пришлось бы передать в JavaScript `AI_REST_TOKEN` и полную преподавательскую карточку.

При отправке вопроса интерфейс передаёт основному backend только:

- вопрос;
- текущую (в том числе ещё не сохранённую) карточку обучающегося;
- идентификатор учебной сессии.

Основной backend сам получает из серверной сессии:

- утверждённую преподавательскую карточку;
- скрытый сценарий заявителя, включая учебный номер обратного звонка;
- историю разговора.

После этого backend выполняет сервер-серверный запрос:

`POST <AI_DIALOGUE_REST_URL>/v1/cards/replies`

с заголовком `Authorization: Bearer <AI_REST_TOKEN>`.

Выделенный AI REST сервер остаётся stateless: историю и карточку он не сохраняет.

## Что изменено в проекте

- `frontend/src/StudentIncidentForm.jsx` передаёт актуальные `card: values` вместе с вопросом. Поэтому ошибочное или ещё не сохранённое поле ученика действительно попадает в контекст диалога.
- `application.py` не вызывает локальный `engine.provider` для полного учебного диалога и предпросмотра заявителя преподавателем.
- `incident_training.py` передаёт текущие поля ученика в доверенный gateway и сохраняет только полученную реплику/историю после успешного ответа.
- `dialogue_gateway.py` подмешивает скрытую преподавательскую карточку и учебный callback-телефон только на backend.
- `ai_rest_client.py` отвечает за защищённый сервер-серверный вызов и никогда не используется браузером.
- `ai_rest_server.py` поддерживает `--host`, поэтому на отдельной машине его можно запустить с `--host 0.0.0.0`.
- лимит истории REST-диалога синхронизирован с приложением: до 50 вопросов.

`student_fields` остаются недоверенными данными. Передача текущей карточки ученика в gateway **не сохраняет её автоматически** и не меняет преподавательский источник истины.

## Вариант 1 — всё на одном компьютере (рекомендуется)

Дважды щёлкните **`START.cmd`**. Больше ничего запускать не нужно.

Главный launcher сам создаёт внутренний REST-токен, поднимает отдельный процесс `ai_rest_server.py` на `127.0.0.1:8890`, проверяет `/health`, затем запускает `web_ui.py` на `127.0.0.1:8878` и открывает браузер. Токен наследуется только серверными процессами и в браузер не передаётся.

Для остановки обоих процессов используйте **`STOP.cmd`**, для полного перезапуска — **`RESTART.cmd`**. Диагностические логи находятся в `.runtime/`.

Ручные команды из старой инструкции для локального режима больше не требуются.

## Вариант 2 — AI REST на отдельном компьютере/сервере

Предположим, IP выделенного сервера: `192.168.1.50`.

### На выделенном AI-сервере

AITUNNEL настраивается **только здесь**. Затем:

```powershell
cd 'E:\гитыч\gt_lct_hackaton'
```

```powershell
$env:AI_REST_TOKEN='ОДИН_ДЛИННЫЙ_СЛУЧАЙНЫЙ_ТОКЕН_НЕ_МЕНЕЕ_24_СИМВОЛОВ'
```

```powershell
py -3.14 ai_rest_server.py --host 0.0.0.0 --port 8890
```

Разрешите входящий TCP-порт 8890 в Windows Firewall **только** от адреса основного backend, если это возможно в вашей сети.

### На компьютере основного приложения

```powershell
cd 'E:\гитыч\gt_lct_hackaton'
```

```powershell
$env:AI_REST_TOKEN='ТОТ_ЖЕ_САМЫЙ_ТОКЕН'
```

```powershell
$env:AI_DIALOGUE_REST_URL='http://192.168.1.50:8890'
```

```powershell
py -3.14 web_ui.py
```

Ключ AITUNNEL в браузер не передаётся. `AI_REST_TOKEN` также не появляется в HTML/JavaScript: он существует только в окружении backend-процесса.

## Проверка

Сначала с машины основного backend:

```powershell
Invoke-RestMethod -Uri "$env:AI_DIALOGUE_REST_URL/health" -Method Get
```

Успешный ответ:

```text
status
------
ok
```

Затем откройте интерфейс обучающегося, начните полную карточку и задайте заявителю вопрос. В Network браузера должен быть запрос к основному API вида:

`POST /api/v1/students/<student>/sessions/<session>/messages`

В нём может быть текущая карточка ученика, но **не должно быть** `AI_REST_TOKEN`, ключа AITUNNEL или `incident_source` преподавателя.

Если выделенный сервер недоступен, интерфейс получает безопасную backend-ошибку о недоступности AI REST. История разговора при неуспешном запросе не дописывается.

## Переменные окружения

- `AI_DIALOGUE_REST_URL` — базовый URL выделенного AI REST; по умолчанию `http://127.0.0.1:8890`.
- `AI_REST_TOKEN` — общий секрет только между основным backend и выделенным AI REST; минимум 24 ASCII-символа без пробелов.
- `AI_DIALOGUE_REST_TIMEOUT` — таймаут server-to-server запроса, по умолчанию 90 секунд, допустимо 1–300.

## Граница изменений

На выделенный REST вынесен именно **контур диалога с заявителем** (ученик и предпросмотр преподавателя). Остальные старые AI-функции проекта — генерация эталона, отдельные legacy-сценарии, оценивание и т.п. — не переписывались на этот endpoint, потому что `/v1/cards/replies` не предназначен для этих операций.
