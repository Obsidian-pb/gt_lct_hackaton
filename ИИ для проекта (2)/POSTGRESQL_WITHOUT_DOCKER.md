# PostgreSQL без Docker

Для локальной проверки серверной версии **Docker и обычная установка PostgreSQL не обязательны**.

## Самый простой вариант

Запустите:

```text
SETUP_SHARED_SERVER.cmd
```

Если Docker отсутствует, откроется меню:

```text
1 - Portable PostgreSQL: скачать и держать внутри проекта
2 - Использовать PostgreSQL, уже установленный в Windows
3 - Подключить внешний PostgreSQL по DATABASE_URL
```

Выберите **1**.

Если предыдущая попытка остановилась на `psql: ... п>їDO`, обновите файлы
проекта из исправленного архива и запустите настройку снова. Установщик
остановит незавершённый экземпляр PostgreSQL, сохранит его каталог под именем
`.runtime/postgres-data-unconfigured-*` и создаст новую базу. Готовая база с
`.env.server` при повторном запуске используется повторно.

Для ошибки `curl: (35) ... CRYPT_E_REVOCATION_OFFLINE` загрузчик применяет
`--ssl-revoke-best-effort` и сохраняет обычную проверку сертификата. Если
скачивание по-прежнему недоступно, скачайте файл
`postgresql-16.15-1-windows-x64-binaries.zip` с EnterpriseDB через браузер
и положите его в `.runtime` проекта, затем снова запустите установщик.

Проект сам скачает официальный архив Windows binaries PostgreSQL 16.15 с EnterpriseDB, распакует его в `.runtime/postgresql`, создаст кластер данных в `.runtime/postgres-data`, выберет локальный порт 55432-55442, создаст БД и пользователя `trainer112`, запишет `.env.server` и применит миграции.

Ничего в Windows устанавливать не нужно. PostgreSQL слушает только `127.0.0.1`, поэтому порт БД не требуется открывать в брандмауэре.

Первичная загрузка PostgreSQL требует интернет. Последующие старты используют уже скачанный runtime.

После настройки:

```text
START_SHARED_SERVER.cmd
```

Если в базе ещё нет пользователей, при первом запуске появятся два запроса
пароля для учётной записи `admin`. Введите пароль длиной не менее 10 символов.
При следующих запусках учётная запись используется повторно.

`START_SHARED_SERVER.cmd` автоматически запускает portable PostgreSQL перед backend. `STOP.cmd` останавливает и backend, и portable PostgreSQL.

Проверка:

```text
http://127.0.0.1:8878/api/v1/health
```

В ответе должно быть `backend: postgresql`.

## Для будущего реального сервера

Portable-вариант удобен для демонстрации и локальной сети. При развёртывании на постоянном VPS/сервере лучше использовать отдельный PostgreSQL (вариант 3) с резервным копированием.
