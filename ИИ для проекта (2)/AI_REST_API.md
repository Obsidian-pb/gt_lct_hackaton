# Отдельный REST API генерации карточек и учебного диалога

`ai_rest_server.py` — отдельный процесс ИИ. По умолчанию он локальный, а для выделенной машины поддерживает `--host 0.0.0.0`. Он умеет:

- сгенерировать черновик учебной карточки: `POST /v1/cards/generations`;
- ответить на один произвольный вопрос обучающегося от лица заявителя: `POST /v1/cards/replies`.

Сервис **не** сохраняет и не публикует карточку, не заполняет поля обучающегося и не хранит историю разговора. Для следующего вопроса вызывающий доверенный бэкенд снова передаёт актуальные поля и `turns`.

## Что является источником истины в диалоге

Для `/v1/cards/replies` рекомендуется передавать полную утверждённую преподавательскую `card`. Сервис валидирует её и формирует для ИИ два доверенных источника:

1. `incident_report` — исходное сообщение преподавательской карточки. Оно имеет наивысший приоритет;
2. структурированные сведения преподавательской карточки, которые заявитель в принципе может знать: имя/роль заявителя, обратный телефон, адрес, ориентиры, обстоятельства, сведения о людях и пострадавших и т.п.

АОН, координаты, данные ВИС, регистрационные поля, классификатор, выбранные службы и контрольные данные не превращаются в знания заявителя.

`student_fields` — только текущие записи обучающегося. Они могут быть ошибочными и никогда не являются подтверждением факта. `turns` нужен для контекста разговора, но предыдущая реплика ИИ также не становится новым источником истины. Если факт отсутствует или помечен как неизвестный/неподтверждённый, заявитель должен сохранить неопределённость, а не делать вывод «нет».

### Защита от выдуманных фактов без разрыва диалога

Если модель всё же сформировала явно неподтверждённый телефон или дословно повторила значение, которое есть только в `student_fields`, REST API не должен отдавать обучающемуся `422 invalid_card`. Сервис автоматически делает одну корректирующую генерацию, не меняя преподавательскую карточку. Если и повторный ответ нарушает проверку, сервис возвращает безопасный `{"reply":"Не знаю."}` с HTTP 200. Это именно аварийная защита: обычные произвольные вопросы по-прежнему обрабатываются моделью по смыслу, а не таблицей ключевых слов.

Для российских телефонных номеров формы `+7 913 ...`, `8 913 ...` и десятизначная запись без первой цифры считаются эквивалентными при проверке, если этот номер есть в доверенных сведениях карточки.

Например, если в преподавательском источнике улица Лесная, а обучающийся записал Сосновую, на вопрос об улице ответ должен опираться на Лесную. Если в источнике сказано «есть ли люди внутри, не знаю», нельзя отвечать, что пострадавших нет или придумывать их количество.

## Безопасная схема подключения

В этой версии проекта связка уже реализована. Браузер обучающегося обращается к REST API основного приложения (`/api/v1/students/.../messages`). Вместе с вопросом он передаёт текущие поля своей карточки, включая ещё не сохранённые изменения. Основной backend получает утверждённую преподавательскую карточку и историю из серверной учебной сессии и затем обращается server-to-server к `<AI_DIALOGUE_REST_URL>/v1/cards/replies` с `Authorization: Bearer <AI_REST_TOKEN>`.

По умолчанию `AI_DIALOGUE_REST_URL=http://127.0.0.1:8890`. Для отдельной машины задайте, например, `http://192.168.1.50:8890`. Полная инструкция находится в `AI_FRONTEND_REST_INTEGRATION.md`.

В браузер обучающегося не должны попадать:

- полная преподавательская карточка/сценарий;
- `AI_REST_TOKEN`;
- ключ AITUNNEL.

Ключ AITUNNEL остаётся в серверной конфигурации `AIProvider`. `AI_REST_TOKEN` — отдельный локальный токен между доверенным бэкендом и этим REST-процессом.

## Настройка AITUNNEL

Запустите `CHANGE_AI_KEY.cmd` и выберите «Другой OpenAI-совместимый API». Для AITUNNEL укажите базовый адрес `https://api.aitunnel.ru/v1`, свой API-ключ и точное имя доступной текстовой модели. Не добавляйте ключ в исходный код, HTML или JavaScript.

## Проверка реального диалога через AITUNNEL

Создайте тестовый запрос. Здесь специально передано ошибочное поле обучающегося `street = Сосновая`, а доверенный источник говорит `Лесная`.

```powershell
$payload = @{ incident_report = 'На улице Лесной возле дома 15 вижу дым из окна третьего этажа. Есть ли люди внутри, не знаю.'; student_fields = @{ street = 'Сосновая'; injured = 'Пострадавших нет'; _report = 'Пострадавших нет'; _class_ids = '[]'; _services = '[]'; _main_service = ''; _flags = '{}' }; question = 'Подскажите, пожалуйста, на какой улице это происходит и что известно о пострадавших?'; turns = @() } | ConvertTo-Json -Depth 12
```

```powershell
$r1 = Invoke-RestMethod -Uri 'http://127.0.0.1:8890/v1/cards/replies' -Method Post -Headers @{ Authorization = "Bearer $env:AI_REST_TOKEN" } -ContentType 'application/json; charset=utf-8' -Body ([Text.Encoding]::UTF8.GetBytes($payload)); $r1
```

Успешный ответ сервиса — HTTP 200 и объект **только** с полем `reply`, например:

```text
reply : Улица Лесная. По пострадавшим не знаю.
```

Точная формулировка может отличаться. Критерий успеха: ответ опирается на Лесную, не принимает Сосновую за факт и не выдумывает число/отсутствие пострадавших. Если реальный AITUNNEL недоступен или его ключ/модель настроены неверно, REST API вернёт `502 provider_error`.

Пример следующего вопроса с историей, которую хранит вызывающий бэкенд:

```powershell
$payload2 = @{ incident_report = 'На улице Лесной возле дома 15 вижу дым из окна третьего этажа. Есть ли люди внутри, не знаю.'; student_fields = @{ street = 'Сосновая'; _report = ''; _class_ids = '[]'; _services = '[]'; _main_service = ''; _flags = '{}' }; question = 'А номер дома какой?'; turns = @(@{ role = 'dispatcher'; text = 'Подскажите, пожалуйста, на какой улице это происходит и что известно о пострадавших?' }, @{ role = 'caller'; text = $r1.reply }) } | ConvertTo-Json -Depth 12
```

```powershell
Invoke-RestMethod -Uri 'http://127.0.0.1:8890/v1/cards/replies' -Method Post -Headers @{ Authorization = "Bearer $env:AI_REST_TOKEN" } -ContentType 'application/json; charset=utf-8' -Body ([Text.Encoding]::UTF8.GetBytes($payload2))
```


> PowerShell сохраняет старое значение переменной `$r1`, если следующий `Invoke-RestMethod` завершился исключением. Поэтому старый `reply`, показанный после ошибки, не является ответом неудачного запроса. Для чистой ручной проверки перед новым запросом можно выполнить `$r1 = $null`.

## Контракт `/v1/cards/replies`

JSON-вариант:

```json
{
  "card": { "...": "полная преподавательская карточка" },
  "student_fields": {
    "city": "Железногорск",
    "street": "Сосновая",
    "_report": "...",
    "_class_ids": "[]",
    "_services": "[]",
    "_main_service": "",
    "_flags": "{}"
  },
  "question": "Произвольный вопрос обучающегося",
  "turns": [
    {"role": "dispatcher", "text": "Что произошло?"},
    {"role": "caller", "text": "Вижу дым."}
  ]
}
```

Передавайте **либо** `card`, **либо** `incident_report`. Полная `card` предпочтительна, потому что даёт модели доверенные дополнительные сведения преподавательской карточки, которые могли не войти в первую реплику.

Допустимые имена `student_fields` совпадают с полной карточкой проекта. В том числе поддерживаются `_report`, `_class_ids`, `_services`, `_main_service`, `_flags`. Значения полей обучающегося передаются строками. История содержит пары `dispatcher`/`caller`, максимум 50 завершённых вопросов.

По умолчанию успешный ответ:

```json
{"reply":"..."}
```

Если передать `format: "text"`, сервис возвращает только текст с `Content-Type: text/plain; charset=utf-8`.

## HTML-формы и три поддерживаемых формата

Маршрут принимает:

- `application/json`;
- `application/x-www-form-urlencoded`;
- `multipart/form-data` (`FormData`).

Для обычной HTML-формы можно использовать `student_fields[city]`, `student_fields[address_text]`, `student_fields[_report]` и т.д. Также поддерживаются прямые имена полей (`city`, `_report`, `_services`...) и совместимый алиас `fields[city]`; все они трактуются именно как **поля обучающегося**. `card`, `turns` и целиком `student_fields` в форме можно передать JSON-строкой.

Проверка `application/x-www-form-urlencoded` одной строкой:

```powershell
Invoke-RestMethod -Uri 'http://127.0.0.1:8890/v1/cards/replies' -Method Post -Headers @{ Authorization = "Bearer $env:AI_REST_TOKEN" } -ContentType 'application/x-www-form-urlencoded; charset=utf-8' -Body @{ incident_report = 'Лесная, дом 15. Вижу дым. Про людей внутри не знаю.'; 'student_fields[street]' = 'Сосновая'; 'student_fields[_report]' = 'Пострадавших нет'; 'student_fields[_class_ids]' = '[]'; 'student_fields[_services]' = '[]'; 'student_fields[_main_service]' = ''; 'student_fields[_flags]' = '{}'; question = 'Где это происходит?' }
```

Проверка `multipart/form-data` через встроенный в современные Windows `curl.exe`:

```powershell
curl.exe -sS -X POST 'http://127.0.0.1:8890/v1/cards/replies' -H "Authorization: Bearer $env:AI_REST_TOKEN" -F "incident_report=Лесная, дом 15. Вижу дым. Про людей внутри не знаю." -F "student_fields[street]=Сосновая" -F "student_fields[_report]=Пострадавших нет" -F "student_fields[_class_ids]=[]" -F "student_fields[_services]=[]" -F "student_fields[_main_service]=" -F "student_fields[_flags]={}" -F "question=Где это происходит?"
```

Файлы во `multipart/form-data` не принимаются.

## Генерация карточки

`POST http://127.0.0.1:8890/v1/cards/generations` принимает только JSON. Пример:

```json
{
  "topic": "Пожар в жилом доме, заявитель видит дым",
  "category": "fire",
  "location": "Железногорск",
  "format": "json"
}
```

Ответ `json` — сам объект карточки: `title`, `report`, `fields`, `class_ids`, `services`, `main_service`, `flags`. При `format: "text"` тот же результат форматируется как UTF-8 текст без второго вызова ИИ.

## Локальные тесты

Тесты REST-диалога используют **подставной провайдер**, а не реальный AITUNNEL. Они проверяют последовательные вопросы, разные формулировки, неизвестные сведения, ошибочные поля обучающегося, реальные имена `_report`, `_class_ids`, `_services`, `_main_service`, `_flags`, JSON, URL-encoded и multipart-запросы.

Из корня проекта:

```powershell
py -3.14 -m unittest discover -s tests -p 'test_ai_rest_server.py' -v
```

Реальную связь с AITUNNEL подтверждает только ручной запрос `/v1/cards/replies` в вашей среде с вашим серверным ключом. `GET /health` и автоматические тесты этого не подтверждают.

## Ограничения и ошибки

- по умолчанию процесс слушает `127.0.0.1`; для выделенной машины используйте `--host 0.0.0.0` и ограничьте доступ к TCP 8890 сетевым экраном;
- `/v1/cards/replies` — до 256000 байт;
- `/v1/cards/generations` — до 16000 байт;
- `401` — неверный `AI_REST_TOKEN`;
- `413` — слишком большой запрос;
- `415` — неподдерживаемый Content-Type;
- `422` — неверная структура карточки/истории/полей либо ответ ИИ нарушил проверяемые ограничения;
- `502 provider_error` — ошибка настроенного ИИ-провайдера, в том числе AITUNNEL;
- сервис не содержит маршрутов публикации или сохранения карточек.

OpenAPI: `GET http://127.0.0.1:8890/openapi.json`.
