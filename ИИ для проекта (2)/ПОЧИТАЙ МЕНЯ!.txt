ПОЧИТАЙ МЕНЯ!
================

АКТУАЛЬНАЯ ВЕРСИЯ ПРОЕКТА
-------------------------
Этот файл описывает основные изменения и текущую логику проекта после всех доработок, сделанных в этом чате.

1. СЦЕНАРИИ И КАРТОЧКИ
----------------------
Теперь сценарий — это каталог карточек.

Пример:
Сценарий «Пожары»
- 40 разных карточек по пожарам
- пожар в квартире
- пожар в жилом доме
- пожар на производстве
- пожар автомобиля
- пожар в общественном здании
и т.д.

Преподаватель может:
- назначить обучающемуся весь сценарий сразу;
- выбрать только отдельные карточки;
- назначить сценарий одному обучающемуся;
- назначить нескольким обучающимся;
- назначить группе.

Сами карточки не исчезают после выдачи и могут использоваться повторно.

2. ПОСЛЕДОВАТЕЛЬНОЕ ПРОХОЖДЕНИЕ
-------------------------------
Если преподаватель назначил несколько карточек, обучающийся проходит их по очереди.

Логика:
1 карточка → сдача → автоматически открывается 2 карточка → затем 3 и т.д.

Обучающемуся не нужно возвращаться в список заданий после каждой карточки.

3. ДВА РЕЖИМА РАБОТЫ
---------------------
Система сложности была полностью убрана.

Теперь используются только два режима:

ОБУЧЕНИЕ
- если обучающийся примерно 10 секунд ничего полезного не делает,
  система показывает одну контекстную подсказку;
- подсказка раскрывает одно ещё не заполненное поле эталонной карточки;
- пример:
  «Подсказка: поле “Адрес” — ул. Ленина, 15»;
- уже заполненные поля повторно не подсказываются;
- каждое новое полезное действие сбрасывает таймер;
- подсказки появляются постепенно.

ТЕСТИРОВАНИЕ
- никаких подсказок;
- эталон не раскрывается;
- система не помогает обучающемуся;
- запрет реализован не только в интерфейсе, но и на сервере.

4. КАРТОЧКА ОБУЧАЮЩЕГОСЯ
-------------------------
Карточка обучающегося приведена к той же структуре, что и карточка преподавателя.

Главное отличие:
- у преподавателя есть эталон;
- у обучающегося поля изначально пустые;
- он заполняет карточку в ходе разговора с заявителем.

В карточке есть:
- телефония;
- регистрационные данные;
- данные заявителя;
- адрес;
- описание происшествия;
- признаки;
- классификатор;
- службы реагирования;
- диалог с заявителем.

5. ДИАЛОГ С ЗАЯВИТЕЛЕМ
-----------------------
Диалог теперь встроен прямо внутрь карточки обучающегося.

Обучающийся:
- пишет вопросы;
- может использовать микрофон;
- получает ответы заявителя;
- слышит озвучивание заявителя.

Поддержана логика Piper.
Если локальный Piper недоступен, используется системный русский голос браузера.

6. КЛАССИФИКАТОР ПРОИСШЕСТВИЙ
------------------------------
Классификатор работает каскадно.

Обучающийся выбирает признаки происшествия.
Система постепенно сужает список возможных классификаторов.

Когда остаётся только один подходящий классификатор:
- он выбирается автоматически;
- дополнительное ручное подтверждение не требуется.

7. АВТОМАТИЧЕСКИЙ ПОДБОР СЛУЖБ
-------------------------------
После выбора классификатора автоматически подбираются службы реагирования.

Обучающийся может:
- оставить предложенный состав;
- убрать службу;
- добавить службу;
- выбрать главную службу;
- вернуть исходный автоматический подбор.

Ручные изменения обучающегося не должны пропадать при обычном пересчёте.

8. БАННЕРЫ ПО КЛАССИФИКАТОРУ
-----------------------------
На экране предварительной информации перед тренировкой блок с текстом:
«Ваша задача — ...»

теперь может иметь разные фоновые изображения в зависимости от классификатора карточки.

Добавлены баннеры:
- утечка газа;
- человек в опасности;
- ДТП с пострадавшими;
- массовое мероприятие;
- пожар на производстве;
- пожар в жилом доме.

Примеры привязки:
- газ / запах газа → баннер утечки газа;
- ДТП → баннер ДТП;
- пожар в квартире / доме → баннер жилого пожара;
- пожар на промышленном объекте → баннер производственного пожара;
- массовое скопление людей → баннер массового мероприятия.

Если для конкретного классификатора баннера пока нет,
используется обычный синий фон.

9. АДМИНИСТРАТОР
----------------
Добавлен отдельный вход под администратора.

При первом входе:
- создаётся локальная административная учётная запись;
- задаются имя, логин и пароль;
- данные не зашиты заранее в проект.

У администратора есть отдельная панель.

Основные разделы:
- Пользователи;
- Тренировки;
- Сценарии;
- Карточки происшествий;
- Результаты;
- Мониторинг;
- Управление системой;
- Настройки.

10. POPUP-ПАНЕЛИ АДМИНИСТРАТОРА
--------------------------------
Интерфейс администратора сделан по макетам VLADIMIR.

Принцип:
- слева постоянное меню;
- основная страница остаётся на фоне;
- разделы открываются справа как большие PopUp-панели;
- фон затемняется;
- внутри есть вкладки, таблицы, фильтры и дополнительные вложенные PopUp-окна.

11. ПОЛЬЗОВАТЕЛИ И ДОСТУП
-------------------------
В административной части предусмотрено:
- добавление пользователей;
- выбор роли;
- блокировка/разблокировка;
- изменение прав;
- просмотр пользователей.

12. ПЕРВЫЙ ЗАПУСК И КЛЮЧ НЕЙРОСЕТИ
-----------------------------------
Проект подготовлен для передачи другим пользователям.

При первом запуске START.cmd:
- программа проверяет, указан ли ключ нейросети;
- если ключа нет, сразу предлагает ввести ключ GigaChat;
- ключ сохраняется только локально у пользователя;
- в ZIP ключ не передаётся.

Для последующей смены ключа предусмотрен:
CHANGE_AI_KEY.cmd

13. ПЕРЕНОСИМОСТЬ
-----------------
Проект можно передавать другим людям.

Важно:
- пользователь использует собственный ключ нейросети;
- личный ключ разработчика в архив не входит;
- пользовательские сессии не должны передаваться;
- интерфейс пересобирается при запуске.

14. START.CMD
-------------
Файлы запуска были исправлены под Windows.

Используется:
- ASCII;
- Windows-переносы строк CRLF;
- без кириллицы в критических строках CMD.

Это исправляет ошибки вида:
'f' is not recognized...
'�' is not recognized...

Запускать проект нужно через:
START.cmd

Если нужно увидеть ошибку в консоли:
START_CONSOLE.cmd

15. КНОПКА ВЫХОДА
-----------------
Исправлена проблема с нечитаемым текстом.

Кнопка «Завершить»:
- тёмный фон;
- белый текст.

Кнопка «Остаться»:
- светлый фон;
- читаемый текст.

16. ГЛАВНАЯ ЛОГИКА РАБОТЫ СИСТЕМЫ
----------------------------------
Общая схема:

Преподаватель
→ создаёт/выбирает сценарий
→ выбирает карточки
→ выбирает режим «Обучение» или «Тестирование»
→ назначает обучающимся

Обучающийся
→ открывает первую карточку
→ разговаривает с ИИ-заявителем
→ заполняет карточку
→ выбирает признаки
→ классификатор определяется автоматически
→ службы подтягиваются автоматически
→ обучающийся при необходимости меняет состав служб
→ сдаёт карточку
→ автоматически получает следующую

Администратор
→ управляет пользователями
→ смотрит сценарии, карточки и тренировки
→ контролирует результаты и систему
→ работает через PopUp-панели
