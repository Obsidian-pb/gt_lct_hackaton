# REST API учебного симулятора 112

Версия API: `1.0.0`. Базовый адрес по умолчанию: `http://127.0.0.1:8878/api/v1`.

## Что перенесено

Веб-интерфейс React, учебный прототип и страница сценариев обращаются к отдельным HTTP-ресурсам. Поле `action` больше не отправляется браузером в сетевом запросе. Внутренние имена `api('card_generate', …)` остаются только удобными именами клиентских функций; общий клиент преобразует их в метод, URL и тело REST-запроса.

- `application.py` — учебные операции и проекции преподавателя/обучающегося без HTTP.
- `api_contract.py` — маршруты, параметры, первичная валидация и спецификация OpenAPI.
- `rest_api.py` — маршрутизация, HTTP-ошибки и обращение к учебному модулю.
- `web_ui.py` — HTTP-транспорт и раздача интерфейса.
- `api_server.py` — отдельный запуск только API.
- `ui/api-client.js` — общий HTTP-клиент React и прежних страниц.
- `openapi.json` — контракт для импорта в Postman/Swagger и согласования с командой.

База данных и пользовательская авторизация не заменялись. Утверждённые задания и учебные работы продолжают сохраняться в `data/`, а черновики мастерской и каталоги сценариев — в существующем localStorage. POST `/cards/generations` возвращает созданное содержимое; публикация в учебный модуль выполняется отдельным POST `/cards/publications`. REST здесь — интерфейс к существующей логике, а не миграция этих данных в новую БД.

## Обычный запуск

Запустите `START.cmd`. Интерфейс работает на прежнем адресе. Документация доступна по `http://127.0.0.1:8878/api/docs`, OpenAPI — по `/api/v1/openapi.json`.

Ключ провайдера ИИ остаётся в `config.local.json` на сервере. Для AITUNNEL используйте окно `CHANGE_AI_KEY.cmd`: «Другой OpenAI-совместимый API», базовый адрес `https://api.aitunnel.ru/v1`, свой ключ и точное имя модели. Смена провайдера не меняет контракт REST API для браузера.

## Запуск только API

API и ключ ИИ — два разных уровня подключения. `TRAINING_API_TOKEN` — отдельный токен доступа к этому учебному серверу; ключ AITUNNEL/OpenAI использовать вместо него не нужно.

В PowerShell из папки проекта:

```powershell
# Токен действует в этой консоли; после её закрытия потребуется задать его снова.
$env:TRAINING_API_TOKEN = [guid]::NewGuid().ToString('N') + [guid]::NewGuid().ToString('N')
py -3 api_server.py --port 8879
```

Токен не выводится сервером и не записывается в ZIP. Передайте это же значение доверенному интеграционному клиенту через его защищённые настройки. Для проверки в той же PowerShell-сессии можно сначала запустить API в отдельном процессе, который унаследует переменную окружения:

```powershell
Start-Process py -ArgumentList '-3','api_server.py','--port','8879' -WorkingDirectory (Get-Location).Path
$headers = @{ Authorization = "Bearer $env:TRAINING_API_TOKEN" }
Invoke-RestMethod 'http://127.0.0.1:8879/api/v1/tasks' -Headers $headers
```

Это альтернативный способ запуска: не запускайте два экземпляра на одном порту. Для Windows также есть `START_API.cmd`; он требует заранее заданный `TRAINING_API_TOKEN`.

Сервер слушает только `127.0.0.1`. Эта версия рассчитана на локальную интеграцию. Для общей сети/публикации команда должна добавить свой серверный контур, TLS и ролевую авторизацию. API-only не выдаёт HTML со служебным UI-токеном.

## Отдельный frontend

Разрешите конкретный Origin при запуске, например:

```powershell
py -3 api_server.py --port 8879 --allowed-origin http://localhost:5173
```

В общем клиенте:

```javascript
import {configure, api, request} from './api.js';
configure({baseUrl:'http://127.0.0.1:8879/api/v1', token: integrationToken});
const tasks = await api('tasks');
// Или напрямую, без внутренних имён операций:
const task = await request('POST','/tasks',{level:'medium',sample:true});
```

`integrationToken` — отдельный токен тестового REST-сервера. Его не нужно вшивать в исходники или хранить вместе с кодом. После подключения командной авторизации замените этот общий интеграционный доступ пользовательской сессией/Bearer-токеном. CORS разрешает только перечисленные Origin и не заменяет проверку токена.

## Запросы и ответы

- `GET` — чтение; параметры только в URL. Никакой генерации и записи учебных данных.
- `POST` — создание/операция. Генерация ИИ, выдача подсказки и сдача работы используют POST.
- `PUT` — сохранение полного редактируемого состояния карточки, заметки или решения.
- Тело POST/PUT: JSON-объект, `Content-Type: application/json`, до 256000 байт.
- Параметры пути не нужно дублировать в JSON. Имена обучающихся в URL кодируются через `encodeURIComponent`.
- Булевы параметры GET: только `true` или `false`, например `?full_form=true`.
- `HEAD` доступен для GET-ресурсов. `OPTIONS` возвращает разрешённые методы.
- Общие заголовки: `X-Request-ID`, `Cache-Control: no-store`. У создания задания/сессии прототипа есть HTTP 201 и `Location`.

Успех:

```json
{"data":{"id":"t-012345abcdef","status":"draft"},"request_id":"идентификатор-запроса"}
```

Ошибка:

```json
{"error":{"code":"state_conflict","message":"Изменять можно только черновик задания."},"request_id":"идентификатор-запроса"}
```

| HTTP | Значение |
|---|---|
| 200 | Операция выполнена или ресурс прочитан |
| 201 | Создано задание/сессия; см. Location |
| 204 | Успешный OPTIONS без тела |
| 400 | Повреждённый JSON или неоднозначные параметры |
| 401 | Нет допустимого токена этого REST-сервера |
| 403 | Запрещённый Origin или несовпадение имени обучающегося |
| 404 | Ресурс/сохранённые данные не найдены |
| 405 | Метод недоступен; разрешённые методы в Allow |
| 409 | Конфликт состояния: например, карточка уже сдана |
| 413 | Тело запроса слишком большое |
| 415 | Не поддерживается Content-Type |
| 422 | Ошибка полей или предметной проверки |
| 500 | Внутренняя ошибка сервера |
| 502 | Ошибка подключённого ИИ/озвучки |

401 от провайдера ИИ приходит как 502 `provider_error` с понятным сообщением: это не тот же токен, что требуется для REST-сервера.

## Примеры JSON-тел

Создать пробное задание без внешнего ИИ — POST `/tasks`:

```json
{"sample":true,"level":"medium","workflow":"caller"}
```

Утвердить — POST `/tasks/{id}/approvals`:

```json
{"teacher":"Преподаватель"}
```

Начать задание — POST `/students/Иванов/sessions` (кодируйте имя в URL):

```json
{"task_id":"t-012345abcdef","full_form":true}
```

Задать вопрос — POST `/students/Иванов/sessions/{id}/messages`:

```json
{"question":"Назовите адрес происшествия","source":"text","full_form":true}
```

Для PUT `/students/{student}/sessions/{id}/card` и POST `…/submissions` передавайте `{"card": {...}, "full_form": true}`. Используйте полный набор полей из GET той же сессии; частичная карточка не принимается.

## Повторы, совместимость и хранение

POST-запросы не повторяются клиентом автоматически. При тайм-ауте операция могла закончиться на сервере — сначала обновите данные. Назначение `training-plans` с прежним `plan_id` повторно использует ранее созданные работы; старт конкретного задания повторно открывает активную сессию. Создание нового черновика через POST `/tasks` не обладает такой защитой и при повторе создаёт новую запись.

Старый `POST /api` оставлен только для внешних старых клиентов, с заголовком `X-Deprecated-API`. Чтобы отключить его, запустите `web_ui.py --no-legacy-api`; в `api_server.py` он всегда отключён. Рабочий интерфейс использует REST в обоих режимах.

После изменения маршрутов выполните `python build_api_contract.py`, затем пересоберите React через `BUILD_UI.cmd`. Перезапустите сервер после обновления Python-файлов.

## Проверка

```text
python -m unittest discover -s tests -v
node tests/check_rest_client.mjs
```

HTTP-тесты запускают сервер с отключённым RPC и проверяют создание/утверждение задания, диалог, сохранение/сдачу карточки, оценку, CORS, токены, безопасные проекции, ошибки, карту и соответствие OpenAPI. Тесты используют искусственные ответы ИИ и временные каталоги.

Основа HTTP-контракта: https://www.rfc-editor.org/rfc/rfc9110.html
Формат спецификации: https://spec.openapis.org/oas/v3.1.1.html
