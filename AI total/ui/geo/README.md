Производная локальная выборка из data/buildings.geojson, roads.geojson и boundary.geojson существующего симулятора. Дата исходной выгрузки неизвестна. Контрольные суммы исходников включены в JSON. Подлинные адресные теги сохранены; отсутствующие номера не синтезируются. Исходный экспорт не сохраняет тип OSM-элемента здания, поэтому ID здания — идентификатор исходной выгрузки, а не гарантированный ID way. Точка здания вычисляется внутри полигона с учётом внутренних колец. Для улицы берётся репрезентативная точка, не точное место происшествия.

Обновление из новых исходников: python tools/build_address_snapshot.py --source <папка с тремя GeoJSON>.
Готовые JSON распространяются вместе с приложением. Автоматической сетевой синхронизации нет.


# Комментарий к получению

## Коротко

Данные — производные от **OpenStreetMap**: это не «сырой» дамп OSM, а результат собственной выгрузки+постобработки трёх слоёв (здания, дороги, граница города) в компактный JSON. Всё это прямо следует из шапки файла.

## Что читается из метаданных

```
"source":"OpenStreetMap", "license":"ODbL-1.0", "atribution":"© OpenStreetMap contributors"
"source_sha256":{"buildings":…,"roads":…,"boundary":…}
"source_export_date":null
```

- Обязательная атрибуция OSM + лицензия ODbL — юридический признак источника.
- **Три хеша = три исходных файла/запроса**: `buildings` (`building=*`), `roads` (`highway=*`), `boundary` (полигон админ-границы Железногорска). Хеши кладут для воспроизводимости: по ним можно сверить, что вход не менялся.
- `source_export_date: null` — дату снимка не зафиксировали (рестр провенанса неполный).
- Один файл = один город → типичная схема «по одному `addresses.json` на город», версия формата `1`.

## Вероятный конвейер

1. **Выгрузка OSM-данных** одним из двух способов:
   - Overpass API: `area["name"="Железногорск"]->.a;` затем `way(area.a)[building];`, `way(area.a)[highway];`, `relation(area.a)[boundary=administrative];` — три отдельных ответа, отсюда и три хеша;
   - либо региональный `.osm.pbf` (Geofabrik/weekly snapshot) + `osmium tags-filter` и `osmium extract --polygon`.
2. **Фильтр по полигону** границы города.
3. **Скрипт-экстрактор** (Python + pyosmium/osmnx/shapely или osm2pgsql+PostGIS): для каждого здания с `addr:housenumber` → запись `{id, kind, street, house, point}`; `point` — центроид полигона здания в порядке **[lon, lat]** (GeoJSON-порядок: 93.55 — долгота, 56.23 — широта).
4. **Сериализация** минифицированным JSON с `ensure_ascii=False` (кирилица не экранирована, файл одной строкой).

## Улики, подтверждающие именно такой путь

- `id: "building-1341097"` — это **OSM way/relation id** с префиксом; значения доходят до `1218375479`, т.е. свежие объекты OSM.
- `id: "street-0" … "street-419"` — **синтетические** id (просто счётчик), т.е. список улиц сгенерирован при экспорте, а не взят из OSM как есть.
- `kind:"street"` с пустым `house` — это названия из слоя дорог, включая улицы СНТ (`СТ № 8`, `СТ № 13/1`), которых в «адресном» виде не существует.
- **Fallback по ближайшей дороге**: `building-524625421` → `"street":"ленинградский"` со строчной буквы — это сырое значение тега `name` с дороги, а не `addr:street`. Значит, у зданий без `addr:street` улица определялась геометрически.
- **Разная точность кординат**: у зданий 7 знаков, у большинства улиц 6 (93.43956, 56.232635) — разная природа геометрии. При этом у части улиц точка **побитово совпадает** со зданием (`street-45` = `building-352126603`, `street-56` = `building-391260984`, `street-120`, `street-133`, `street-204`, `street-239`) — эти улицы известны только из `addr:street`, и точку для них взяли от здания.
- **Нет нормализации и дедупликации**: `7 с1`, `48А/1`, `сор26В/1`, `95/16` (дважды, разные точки), два разных объекта с «проспект Курчатова, 42», `улица Царевского` и `улица Генерала Царевского` как разные значения. Это механический дамп тегов, а не результат геокодера (Nominatim/ГИАС дал бы нормализованные, дедуплицированные адреса).

## Как проверить гипотезу

- Взять любой id (`building-1341097`) и открыть `https://www.openstreetmap.org/way/1341097` — должен существовать и содержать `addr:street`/`addr:housenumber`.
- Скачать кандидат-экстракт (Overpass-запрос или osmium-вырезку по полигону) и посчитать `Get-FileHash -Algorithm SHA256` — совпадение с `source_sha256` доказывает конкретный вход.
- Проверить, что все `point` лежат внутри полигона границы, а `kind:"street"` покрывает все уникальные `street` из записей зданий.
