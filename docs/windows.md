# Запуск на рабочем месте под Windows 10/11

Комплекс поставляется готовым: всё, что нужно для работы, уже внутри
поставки, и работает он целиком в локальной сети учебного центра. Ниже два
способа установки — контейнеры через Docker Desktop (путь А) и переносной
комплект без Docker (путь Б). Ни Python, ни Node.js, ни PostgreSQL на
компьютер ставить не нужно.

## Что понадобится

- Windows 10 21H2 и новее или Windows 11, 64-разрядная.
- **Docker Desktop** с движком WSL 2. Ставится с правами администратора,
  после установки может попросить перезагрузку.
- Память: не меньше 8 ГБ на компьютере. Docker Desktop сам ограничивает
  память для WSL; чтобы контейнеру с моделью хватило, создайте файл
  `C:\Users\<имя>\.wslconfig` с содержимым:

  ```
  [wsl2]
  memory=8GB
  processors=4
  ```

  и перезапустите Docker Desktop.
- Свободное место: около 12 ГБ (образы, модель, база).

Все команды ниже — в PowerShell, из папки поставки.

## Путь А. Контейнеры из архива поставки

Поставка — папка `dds112-deploy` с файлами развёртывания и архив образов
`dds112-images.tar`.

1. Загрузить образы и заполнить настройки:

   ```powershell
   cd dds112-deploy
   docker load -i ..\dds112-images.tar
   Copy-Item .env.example .env
   notepad .env
   ```

   Содержимое `.env` (Блокнотом, кодировка UTF-8):

   ```
   DB_USER=trainer
   DB_PASSWORD=придумайте
   DB_NAME=trainer
   SECRET_KEY=любая-случайная-строка-не-короче-32-символов
   DEMO_PASSWORD=пароль-учебных-учётных-записей
   WEB_PORT=8090
   ```

   Если порт 8090 на компьютере занят — поставьте другой, например 8091.

2. Запустить:

   ```powershell
   docker compose -f docker-compose.prod.yml -f docker-compose.offline.yml up -d
   ```

   Образы уже загружены, собирать ничего не нужно. Контейнер `llm` доходит
   до состояния `healthy` за 1–3 минуты — он загружает модель в память.

3. Открыть <http://localhost:8090> (или свой порт). Учётные записи:
   `admin`, `teacher`, `student`, `student2`; пароль — `DEMO_PASSWORD` из `.env`.

## Путь Б. Без Docker — переносной комплект

Проверен заказчиком на рабочем месте под Windows 24 сентября 2026:
запустился с первого раза, без правок.

Для рабочего места, где нет Docker и прав администратора. Архив
`dds112-portable.zip` (~2,7 ГБ) собирается на машине разработчика
(`scripts/package_portable.sh`) и содержит всё: встраиваемый Python
с зависимостями, PostgreSQL 17, сервер llama.cpp, модель Qwen3 4B, код
и интерфейс. В систему ничего не устанавливается, порты открываются
только на `127.0.0.1`.

1. Распаковать архив на диск (не на флешку: база пишет на диск).
2. Дважды щёлкнуть `start.cmd` — обычным щелчком, **не** «от имени
   администратора»: PostgreSQL с правами администратора не запускается.
3. Первый запуск 1–2 минуты: создаётся база, загружаются билеты; затем
   открывается браузер с <http://127.0.0.1:8090/>. Модель загружается
   в память ещё 1–3 минуты.
4. Остановка — `stop.cmd`. Данные остаются в `data\`.

Порт, число ядер для модели и пароль учебных учётных записей меняются
в `settings.cmd` (образец — `settings.example.cmd`). Журналы — `data\logs\`.

**Доступ ученикам из класса.** По умолчанию комплект открыт только на этом
компьютере. Строка `set "WEB_HOST=0.0.0.0"` в `settings.cmd` открывает
веб-интерфейс по адресу компьютера в сети (`start.cmd` покажет ссылки вида
`http://192.168.10.10:8090/`); база и модель наружу не открываются. При
первом запуске Windows спросит про брандмауэр — разрешить доступ в частных
сетях; на это нужны права администратора один раз, иначе входящие
соединения останутся закрытыми.
Подробная памятка лежит внутри комплекта: `README-ЗАПУСК.txt`.

Обновление после правок кода — `dds112-update.zip` (~15 МБ,
`scripts/package_portable.sh --update`): остановить, распаковать поверх
папки с заменой, запустить — миграции применятся сами.

## Что проверить

1. **Модель отвечает.** Войти `admin` → «Настройки» → «Проверить связь».
   Ожидается «Модель «qwen» ответила за … мс». Там же видно, что провайдер —
   `local`, адрес — `http://llm:8080/v1`.
2. **Работа в локальной сети.** Войти `student` с другого компьютера класса
   по адресу этого компьютера, принять вызов, спросить заявителя, сдать
   карточку. Звук играет, оценка выставляется сразу, разбор и ответы
   заявителя приходят от модели на этом же компьютере — все компоненты
   комплекса работают здесь, внешних подключений он не делает.
3. **Яндекс.Браузер.** Пройти то же самое в нём: вход, вызов с озвучкой,
   карточка диспетчера, отчёт преподавателя с выгрузкой PDF.
4. **Состояние системы.** `admin` → «Состояние системы»: все компоненты
   зелёные, есть отметка о резервной копии после первой ночи.

## Если что-то не так

| Признак | Причина и действие |
|---|---|
| `llm` долго `starting`, потом `unhealthy` | Не хватило памяти. Проверить `.wslconfig` (см. выше), перезапустить Docker Desktop, затем `up -d` снова |
| `bind: address already in use` для `web` | Порт занят. Сменить `WEB_PORT` в `.env` и повторить `up -d` |
| Разбор от модели не появляется, оценка есть | Так и задумано при недоступной модели. Проверить `docker compose … logs llm` и связь в «Настройках» |
| После перезагрузки Windows стенд не поднялся | Docker Desktop не запущен автоматически. Запустить его; контейнеры стартуют сами (`restart: unless-stopped`) |

## Остановка и удаление

```powershell
docker compose -f docker-compose.prod.yml -f docker-compose.offline.yml down      # остановить, данные сохранить
docker compose -f docker-compose.prod.yml -f docker-compose.offline.yml down -v   # остановить и удалить базу
```
