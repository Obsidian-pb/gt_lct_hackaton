# Пожелания руководителя команды — что у нас реализовано

Источники — документы О. С. Малютина в репозитории команды (ветка `work`):
`workflow/database_remarks.md` (разбор полей карточки), `tz_simple.qmd`
(ТЗ без повторов), `bizprocesses.qmd` (сценарии работы), `tz_for_rork.qmd`
(окна, редакция 25.09), `inner_terms.qmd` (термины), `workflow/ideas.md`,
`tasks.md`. Перечень окон разобран отдельно — `docs/windows-map.md`.

Обозначения: ✓ сделано; ≈ сделано иначе или частично; ✗ нет.

## Процесс обучения (tz_simple, bizprocesses)

| Пожелание | | Как у нас |
|---|---|---|
| Учебная копия системы-112 в закрытом контуре, без интернета | ✓ | модель в контейнере или в переносном комплекте; проверено на Windows без сети |
| Вызовы «настоящие на вид», генерирует ИИ | ✓ | генерация моделью в фоне + 96 реальных экзаменационных билетов с озвучкой |
| Эталон генерирует ИИ, утверждает преподаватель | ≈ | эталон даёт классификатор (тип, службы), модель пишет обращение; без утверждения в занятие не идёт |
| Корректировка генерации комментарием («перепиши…») | ✓ | замечание к сценарию — переработка с его учётом |
| Эмуляция вызова: голос через SIP/VoIP или текст | ≈ | озвученная запись вызова и диалог с заявителем; SIP нет — в ограничениях |
| Карточки одна за другой, пока преподаватель не завершит | ✓ | поток с интервалом; занятие можно завершить в любой момент |
| Таймер, норматив 30 с, настраивается | ✓ | два норматива: взятие 30 с, обработка 180 с — на занятие |
| Сценарий 2: «заполни карточку с нуля» | ✓ | режим оператора 112 |
| Сценарий 3: «действуй с готовой карточкой», ввод текста ответа | ✓ | режим диспетчера ДДС: статусы реагирования с комментариями |
| Источник карточек: сгенерированные / составленные обучающимися / смешанные | ≈ | сгенерированные, билеты, созданные вручную; составления карточек самими обучающимися нет |
| Случайная выдача карточек | ✓ | порядок перемешивается для каждого обучающегося |
| Статусы тренировки: подготовленная → активная → завершённая | ✓ | черновик → идёт → завершено; завершённое не редактируется |
| Мониторинг хода занятия в реальном времени | ✓ | монитор занятия, главная преподавателя |
| Профильная лента: обучающемуся — только профильные события | ≈ | диспетчер получает карточки своей службы; непрофильные — намеренно, для проверки отказа |
| Ролевая модель: какие категории в ленту каких групп | ≈ | состав занятия и сценарии задаёт преподаватель; привязки «категория → группа» нет |
| Проверка грамматики, в т.ч. принудительная после правок | ✓ | в разборе и кнопкой у сценария |
| Пороги допустимых грамматических ошибок настраивает преподаватель | ✗ | замечания к грамматике есть, в зачёт они не входят и порога нет |
| Итог = автоматическая + экспертная; изменение — в журнал аудита | ✓ | итоговый балл преподавателя, аудит «было / стало / обоснование» |
| Комментарий преподавателя к карточке и к тренировке | ≈ | к работе — да; к занятию целиком — нет |
| Отчёт: действия, ошибки, время, отклонение, грамматика; прогресс по группам | ✓ | отчёт занятия, «Работы», кабинет обучающегося |
| Инсайты ИИ по типичным ошибкам группы | ≈ | сводка системных ошибок группы считается по каталогу, без модели |
| Экспорт CSV, PDF (опционально XLSX) | ≈ | CSV и PDF; XLSX нет |
| Справочная база | ✓ | тексты и файлы |
| Бэкап не реже раза в сутки, автовосстановление, мониторинг | ✓ | контейнер копий / копии при запуске и остановке комплекта |

## Идеи и задачи

| Пожелание | | Как у нас |
|---|---|---|
| Режим обучения с подсказками, что куда вводить (после 5 с бездействия) | ✗ | есть инструктаж перед занятием и обоснование в разборе; подсказок у полей по ходу нет |

## Итог

Из 40 пожеланий: 24 сделано, 10 сделано иначе или частично, 6 нет. Из шести
отсутствующих два сознательные (страна и координаты; адаптивная сложность),
два — вне материала билетов («нет контакта», «срыв звонка»), и два — идеи
на следующую версию: **режим «Обучение» с подсказками у полей** и
**порог грамматических ошибок**. Обе реализуемы без интернета.
