# Карточка оператора по образцу АРМ-112 — контракт между бэкендом и фронтом

Источник компоновки — скриншот настоящего АРМ-112 из репозитория команды
(`TZ/imgs/card_0.png`, снят 17.09.2026): сверху телефоны и таймер, слева
заявитель и адрес, справа классификатор кнопками и **кнопки признаков**
(«Пострадавшие», «Нет на месте / Отказ от скорой», «Нет доступа /
Заблокированные»), снизу полоса служб. Признаки в настоящей системе
отмечает оператор, и от них зависит список оповещения — это и есть
предмет обучения, а не деталь оформления.

Этот файл — договорённость на время параллельной разработки: бэкенд и фронт
делаются отдельно и сходятся по нему. После слияния он остаётся описанием API.

## Данные

- `Attempt.chosen_flags: list[str]` — признаки, отмеченные оператором
  (миграция `b8e2f4a61c07`, уже в `main`). Эталон — `Scenario.flags`.
- Ключи признаков — как в классификаторе (`VARIANT_FLAGS` в
  `services/ekp_import.py`): `пострадавшие`, `пострадавшие_не_на_месте`,
  `нет_доступа`, `угроза_людям`, `правонарушение`, `газификация`,
  `мед_помощь`, `эвакуация`, `массовое`, `перекрытие_движения`, `тоннель`,
  `пешеходный_переход`, `пожар`, `объект_из_перечня` и другие, какие есть
  в `data/ekp.json`. Названия для кнопок даёт бэкенд (см. ниже), фронт
  ключи не расшифровывает.

## API оператора (`/api/operator`)

### `GET /calls/{id}` — `CallOut`, добавлено

```json
"chosen_flags": ["пострадавшие"]
```

### `POST /calls/{id}/classify` — `ClassifyIn`, добавлено

```json
"flags": ["пострадавшие", "нет_доступа"]
```

Неизвестные ключи отклоняются с 422 и перечнем допустимых.

### `GET /flags?attempt_id=&group=&path=` — новое

Какие признаки показывать. `path` — через `|`, как в `/options`.

```json
{
  "global": [
    {"key": "пострадавшие", "title": "Пострадавшие", "hint": "Есть пострадавшие или погибшие"},
    {"key": "пострадавшие_не_на_месте", "title": "Нет на месте / Отказ от скорой", "hint": "..."},
    {"key": "нет_доступа", "title": "Нет доступа / Заблокированные", "hint": "..."}
  ],
  "rule": [
    {"key": "угроза_людям", "title": "Угроза людям", "hint": "..."},
    {"key": "газификация", "title": "Проведена ли газификация", "hint": "..."}
  ]
}
```

`global` — три кнопки, как в АРМ-112, всегда. `rule` — признаки, которые
встречаются в подколонках оповещения у правила, к которому ведёт `group` +
`path` (только подколонки, где служба реагирует), без трёх глобальных.
Пока путь не доведён до правила — `rule: []`. Редакция классификатора —
редакция занятия (`ekp_for_session`), как у `/options`.

### `GET /preview?attempt_id=&group=&path=&flags=a|b` — новое

Список оповещения по **выбору оператора** — то, что настоящий АРМ-112
показывает в нижней полосе служб по мере заполнения. Это не подсказка
эталона: считается по правилу, которое выбрал оператор, с его признаками.

```json
{
  "incident_type": "пожар: мусор",
  "services": [
    {"service": "МЧС", "incident_type": "пожар: мусор", "notified": true,
     "reason": "оповещается при этом типе происшествия всегда"},
    {"service": "СМП", "incident_type": "пожар", "notified": true,
     "reason": "потому что отмечен признак «пострадавшие»"}
  ]
}
```

Только `notified: true` (в предпросмотре неоповещённые не нужны).
Путь не доведён — `{"incident_type": null, "services": []}`.
Формат элемента — `NotificationReasonOut` (`schemas/training.py`).

### `ClassificationOut` в ответе `classify`, добавлено

```json
"expected_flags": ["пострадавшие"],
"chosen_flags": [],
"missed_flags": ["пострадавшие"],
"extra_flags": []
```

`missed_services` и `extra_services` считаются как
`expected.resolve(expected_flags)` против `chosen.resolve(chosen_flags)`:
пропущенный признак проявляется как неоповещённая служба.
`notified_services` и `notification_reasons` — по эталону с эталонными
признаками, как сейчас.

## Оценка (`services/operator.py`)

- `FilledCard.flags: frozenset[str]`; `Expected.flags` уже есть.
- `survey.classify(..., flags=expected_flags, chosen_flags=...)`: без
  `chosen_flags` ведёт себя как сейчас (одни флаги с обеих сторон) — так
  остаются верными вызовы из карточки диспетчера и кабинета преподавателя.
- Новые нарушения в каталоге (`services/violations.py`, после `O13`):
  - `O14` «Признак опросной карты не отмечен», критическое, критерий полноты:
    в вызове есть признак, оператор его не отметил, и из-за этого служба
    не оповещена. В `detail` — какой признак и какие службы не получили бы
    оповещение. Признак без последствий для списка нарушением не считается.
  - `O15` «Отмечен признак, которого нет в вызове», значимое: лишний признак
    добавил в оповещение службу без оснований. В `detail` — признак и службы.
- Балл: пропущенный признак с последствиями снижает долю классификации так
  же, как ошибка признака пути, — через `missed_services` он уже это делает;
  отдельного коэффициента не вводить.

## Что не входит

- Телефон «на месте» как отдельное поле ввода — у попытки его нет; в шапке
  показываются АОН (только чтение) и названный заявителем.
- Округ и район остаются справочными; страна и координаты не вводятся.
- Сценарий обучающегося «инструктаж → сеанс → результат» — отдельная
  работа после слияния этой.
